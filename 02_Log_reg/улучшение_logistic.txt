Что делать дальше (ваш план улучшения)
Так как ваша базовая Logistic Regression без балансировки выдала перекос в сторону мажоритарного класса (1), вам нужно двигаться в одном из двух русел (или комбинировать их):

Русло 1. Балансировка классов (самое важное)
В вашем LogisticRegression() есть параметр class_weight. Поставьте его в 'balanced', и алгоритм начнет штрафовать за ошибки по классу 0 сильнее.

python
model_balanced = LogisticRegression(class_weight='balanced')
После этого вы увидите, что Recall для класса 0 вырастет (станет ближе к 0.7–0.8), но при этом Precision для класса 0 упадет (мы начнем чаще ошибаться и отказывать хорошим клиентам). Это ровно тот компромисс, о котором вы говорили в прошлом сообщении! Только теперь вы применяете его к классу 0.

Русло 2. Сдвиг порога решающего правила
Сейчас модель режет вероятности по порогу 0.5. Чтобы увеличить Recall по дефолтам (класс 0), вам нужно понизить порог для класса 0 (или, что то же самое, предсказывать класс 1 только при очень высокой уверенности).
Попробуйте вместо predict использовать predict_proba и вручную назначать класс 0, если вероятность класса 0 > 0.3 или 0.4.

Русло 3. Признаки
Посмотрите на тепловую карту корреляций. Если ни один признак не коррелирует с kredit сильно (выше 0.3), возможно, нужна генерация новых признаков (полиномиальные фичи) или отбор самых значимых через коэффициенты модели, чтобы убрать шум.
